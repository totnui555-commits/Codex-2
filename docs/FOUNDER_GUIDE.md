# Founder onboarding

1. Open the private installation and initialize your owner account with the deployment setup token. For this local workspace only, generated private sign-in details live in ignored `.local/owner-credentials.json`.
2. Explore Office or accessible 2D view. Click floors or agents. Idle means no actual running model job; no decorative movement is presented as work.
3. Create a project and a task with concrete acceptance criteria. A chief_of_staff task plans and delegates a typed DAG once model/storage/budget connections are available. An engineering task uses the bounded CRUD sandbox pipeline after build_autopilot authorization.
4. Read Founder Inbox for missing provider connections and critical decisions. Enter credentials in the deployment secret manager, never chat, source files or Inbox responses. The consolidated setup request was emailed through your authorized connected chat Gmail; application OAuth remains separate.
5. In Settings, choose your mode and ceilings. Paid execution stays disabled until you explicitly opt in. Research-only public API collection can operate without paid models. It does not publish offers or contact prospects.
6. Opportunities show actual source links and heuristic scores with uncertainty. Create an incubation backlog from a candidate; this is an internal project, not proof of market demand.
7. Inspect approval action/target/hash/expiry/exposure before approving. An Inbox reply, email reply or silence is not a release approval. Production deployment is a separate unsupported gate until wired and reviewed.
8. Use STOP ALL whenever needed. Gates close immediately; review provider status for confirmed remote termination. Quarantined tasks need explicit investigation, not automatic resume.
9. Finance distinguishes verified live gross receipts and refunds from estimated spend and unknown net contribution. No revenue has been invented or generated by the current setup.

# API and execution contracts

FastAPI exposes typed OpenAPI at /openapi.json and /docs. All management routes require an owner session except /health and first-installation /auth/bootstrap. Authenticated organization selection uses X-Organization-ID (or organization_id for EventSource), verified against membership. Cross-tenant IDs return 404/403.

Core: /auth/bootstrap, /auth/login, /auth/me, /auth/logout; GET /snapshot; POST /projects; PATCH /projects/{id}; POST /tasks; POST /tasks/{id}/dependencies/{dependency}; /cancel and /retry; /company/stop, /company/resume, PUT /company/policy; /approvals and /approvals/{id}/decide; /inbox/{id}/respond; /opportunities/{id}/incubate; /audit and /audit/verify; /events/history and streaming /events; /artifacts/{id}/content; /tasks/{id}/accept-artifact/{artifact_id}.

Events include id (event_id), organization_id, aggregate_type/id/sequence, event_type, created_at (occurred_at), actor_type/id, correlation_id, causation_id, payload, schema_version and monotonically allocated cursor. At-least-once consumers deduplicate by event id and replay after cursor. Snapshots carry the highest tenant cursor under the organization lock; clients refresh authoritative state after events and use Last-Event-ID or after to reconnect. Session revocation closes existing SSE connections. Schema aliases are documented; no field is inferred from client animation.

Task states and legal transitions are centralized in domain.py. Only engine/verified artifact acceptance can mark completion. The Chief of Staff returns bounded PlannedTask contracts with configured roles and earlier-index dependencies; arbitrary commands or policy changes cannot be supplied. Specialists return typed reports with limitations and wait for independent/owner evidence review. The coding factory exports files and evidence, independently verifies checksums and hosted CRUD acceptance, and submits a draft PR; code/test success is not a production release.

Protected actions bind approvals to SHA-256/target/exposure/expiry and consume them once. The model gateway accepts only a signed expiring capability for a running run with an active reservation; no user session substitutes for this capability. Stripe webhooks require a valid fresh signature, live settled event and matching signed organization metadata. Email sending uses only the configured founder destination and authorized OAuth.
